# Approved Hyperliquid and Lighter workflows

Manual Workflow tickets run the selected original graph through the normal ticket confirmation. Enter a maximum total quote notional, select exact account/mode and base amount, review all nodes and connections, then Run. AI-prepared graphs require one chat approval of the entire plan. Neither saving a definition nor approving an ordinary single entry starts a workflow.

The Hetzner bridge persists original core graphs: Order Input, market and limit orders, take-profit, stop-loss, condition, parallel split and wait. Conditions evaluate fresh prices once and route pass/fail branches as the original engine does. Joins wait for every parent path and execute when at least one path is live. Percentage sizing and price offsets remain formulas until execution; confirmed parent fill quantities/prices propagate to dependents. Fixed amounts/prices must satisfy venue precision. Waits survive service restarts without blocking independent branches. The former 20-order and 48-hour plan limits are removed. Finite acyclic graphs, HTTP resource limits and account risk guardrails still apply; unknown plugin-defined server execution types are explicitly rejected.

OCO uses verified exchange-specific paths. Lighter pairs same-sized reduce-only TP/SL using native grouped orders type2, after a confirmed entry fill or against a verified existing position. Hyperliquid submits an entry and full-size TP/SL together in a native normalTpsl batch. Each bracket entry may connect directly or through a Split to its exits; multiple independent brackets are supported. Its percentage exit targets use the entry limit price or fresh quote before grouped submission. Partial-size Hyperliquid attached OCO requires a separately sized parent entry; ordinary non-OCO protection nodes retain percentage-sized exits. Spot trigger/OCO execution remains unavailable where connector support is not verified.

Ask **Check my workflow runs** for actual persisted schedules, node outcomes and **Stop future workflow steps**. This stops future submissions; existing exchange orders/positions remain. Completed means the workflow's actions were submitted or simulated, not that every resting order filled. Native pending bracket children remain conditional on the exchange's parent-fill rules. Old drafts never auto-start.

Data lives in `data/workflow-runs.sqlite` under the bridge's shared working directory. Kill switch, changed account/mode/credentials, unavailable/stale market data, violated exchange rules, exhausted daily limits, a crossed approved budget or uncertain submission pauses the run. A restart during submission never retries that order. Confirmed pending entry fills are reconciled without resubmitting. Manual orders remain direct; the scheduler does not expose operator credentials to agents or enable the upstream unattended-order bypass.
