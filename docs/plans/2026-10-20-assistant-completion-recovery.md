# Assistant response recovery — 20 October 2026

Hosted diagnostics reproduced Xiaomi MiMo v2.6 Flash returning HTTP 200 and then breaking its SSE response after 72–80 seconds. Retrying the incomplete step doubled the wait. Moving inference to an independent worker protected it from bridge restarts, but did not resolve the provider's response failures.

Release `20261020-6` requests complete JSON responses for atomic inference. Validated text, reasoning, tool identities, complete JSON arguments and usage are converted to the SDK's existing resumable SSE contract. Partial responses, duplicate tool identities and token-limited completions cannot release tool calls. Existing SSE-only and legacy non-atomic clients remain supported. Retries affect only an unexposed inference step, never completed tools or exchange actions.

MiMo also stalled on complete JSON, so the user-authorized alternative was activated through Settings → Intelligence → Manage providers: `minimax/minimax-m2.7`, with the existing key and server-backed mode retained. A fresh read-only conversation completed four scanner/detail calls and a report without retries; measured model steps took 19.5, 16.4 and 39.6 seconds. Another continuation completed in 11.9 and 30.8 seconds. These timings are observations, not a latency guarantee. No financial actions were performed.

Verification: 367 backend tests pass both in the staged source snapshot and on Hetzner; staged TypeScript passes; 123 Hummingbot Python tests pass with the pinned upstream source present. The 32 focused inference tests include five new complete-response regressions. A real AI SDK compatibility check verifies exactly one tool execution with its original identity and arguments. Public HTTPS/session authorization and private job access checks pass. Deployment waited for resumable output retention to expire, then restarted only inference; bridge and exchange services were unchanged.

Remaining work is separate: full Trading Agents Live/Paper integration and UI/draft review are not deployed by this release. Also found a Plugins-store configuration form that reads App Server defaults instead of the local configuration ledger; the Settings → Intelligence provider wizard correctly reads the saved model and key. No secrets were inspected or copied during diagnosis. Provider availability and model output quality cannot be guaranteed by transport recovery.
