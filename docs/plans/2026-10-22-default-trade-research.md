# Default trade research

New entry decisions use a compact public scanner overview, relevant dated news, market structure and material event risk. Discovery compares up to three distinct candidates; named trades stay focused. Before preparing an order the existing exact-account, fresh quote/book, exposure, contract and risk checks remain required. Account reads are not needed for public-only comparisons. Unknown or failed sources are disclosed, not scored positively.

The new get_trade_research_brief reads one existing scanner snapshot and derives six top-three views: raw gainers, losers, BTC-relative leaders, funding/crowding, funding differences and mark gaps. It reports native identities, source freshness and partial coverage. Whole rows are omitted explicitly if the 12k-character cap is reached. No options context is invented for unrelated assets; the existing options tools remain available when relevant.

Default guidance reuses fresh current-turn results, avoids duplicate scans and raw-data dumps, and limits news fallback to one focused full-name web search. Explicit deep research can expand this. Closing/cancellation/status and urgent risk reduction do not wait for broad research. Existing 80k model history limits and confirmation/execution safeguards are unchanged. These are default model instructions, not a profitability guarantee or a new execution authority.

General get_news requests now honor the documented no-symbol scope instead of silently using the on-screen chart coin. Explicit ticker reads are unchanged. Regression tests cover this scope change and public scanner input/output bounds, source failures, staleness, exact builder identifiers and a single snapshot read.

Hosted pilot: a research-only Lighter request automatically called the compact brief, then news/web, scanner histories, chart/confluence, book and tape reads. It returned a conditional wait/retest idea with counterevidence and prepared no order. The pilot mislabeled negative funding as long crowding, so the final brief supplies a computed fundingPayer enum (longs/shorts/none/unknown) and explicitly states positioning is not measured. Guidance also requires matching the full project and named news source entity. Regression tests verify both funding signs, zero and missing rates without treating the proxy as measured positioning. These improvements reduce ambiguity; they do not make model judgment infallible.

Final verification: full 4,150 frontend suite plus later focused context and funding tests pass; strict TypeScript, focused ESLint and the 11-task production build pass. Deployed frontend-only 20261022-2 with public/session/scanner-history checks. A final live brief request correctly copied longs/shorts payer labels and explicitly said positioning was not measured. No trade was prepared/submitted and no exchange service was restarted.
